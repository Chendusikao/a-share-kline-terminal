# 情侣旅行作品集：日光公路片设计规范

## 1. 项目定位

这是一个可公开分享的情侣旅行影像作品集。它不是传统的照片相册：访客先进入一段有镜头感的公路旅程，再沿着年度章节、地点停靠站和照片片段深入浏览。

**核心体验**：明亮的白天风景是主角；情侣关系以一句旁白、日期和路线细节自然出现，不把私密内容暴露为页面主体。

**首版目标**：让第一次访问者在 30 秒内理解“这是谁的什么旅程”，能流畅地进入任一年份、任一地点并查看相片；每个地点都有可单独分享的页面。

**不在首版范围内**：评论、账号体系、访客上传、原始照片下载、强制性 3D 场景和自动播放音视频。

## 2. 已确认的设计决策

- 受众：公开浏览的旅行作品集。
- 视觉：日光电影感公路片。使用蓝天、暖白高光、海岸/山路色块和缓慢镜头节奏，不使用压暗白天照片的重滤镜。
- 首页：章节式旅程；中段嵌入轻量地图，而非以地图作为首屏。
- 叙事：三年三幕，地点是每一幕中的停靠站。
- 动效：轻视差、淡入和章节转场；照片优先。3D 是可关闭的第二阶段增强能力。

## 3. 内容与章节

| 幕次 | 年份 | 章节标题 | 停靠站 |
| --- | --- | --- | --- |
| 序幕 | 2024 | 从天津，第一次出发。 | 天津滨江道、天津滨海新区 |
| 第二幕 | 2025 | 海风之后，是北京的灯。 | 北戴河、北京 |
| 第三幕 | 2026 | 向南，故事还在路上。 | 济南、南京 |

每一幕固定按以下节奏展示：章节海报 → 一句旁白 → 两个地点停靠站 → 路线小地图 → 3–5 张精选照片组成的片段 → 一段“路上笔记” → 下一幕预告。

每个地点页包含一张全景首图、地点/日期、短故事、照片序列、相邻地点导航和返回所在章节入口。地点页有独立链接，便于公开分享。

## 4. 信息架构与浏览路径

主导航只保留四项：

1. **首页**：公路电影式首屏，向下滚动即进入第一幕。
2. **旅程章节**：按 2024、2025、2026 浏览完整三幕。
3. **旅程地图**：快速跳转至六个地点；地图是检索入口，不抢首屏叙事。
4. **全部片段**：按年份或城市筛选的照片集合。

典型路径是“首页 → 年度章节 → 地点页 → 照片全屏查看 → 上一/下一站”。任意时刻都可通过地图跳至地点，或通过全部片段回看影像。

## 5. 视觉系统

### 色彩与图像

- 基底：奶油白 `#F5EFE3`，保证日间风景的留白和阅读舒适度。
- 深色：公路蓝灰 `#1C3340`，用于导航、页尾和文字对比。
- 强调：日晒金 `#D9B778`、路牌橙 `#A2644E`、植被绿 `#576A4E`。
- 图片保留真实高光和蓝天，不采用全站统一暗调。章节首图使用轻微色温统一，不覆盖场景本身的时间感。

### 字体与版式

- 标题使用具有叙事感的衬线字；正文、日期、坐标使用清晰的无衬线字。
- 桌面端以全宽章节海报和宽松留白建立镜头感；手机端改为单栏，首图高度控制在不遮挡首句标题的范围内。
- 手帐元素仅用于日期、坐标、票根和一句私语；每屏最多一处，绝不覆盖照片主体。

## 6. 交互、无障碍与性能

- 首屏与章节之间使用 0.6–0.9 秒淡入/推进行为；不使用自动播放的背景视频。
- 点击地点停靠站进入地点页；照片支持点击全屏、滑动、键盘切换和明确的关闭/返回操作。
- 环境声默认关闭；如在后续版本加入，始终提供可见的播放与静音控制。
- 遵从系统“减少动态效果”偏好，并提供手动减少动效选项。此时取消视差和非必要转场。
- 低网速、WebGL 不可用或低性能设备下，展示静态照片、文本和地图，不阻塞内容阅读。
- 图片提供有意义的替代文本；键盘可访问导航、地点、照片查看器和动效控制。

## 7. 内容模型与数据流

首版内容以版本化 JSON 或 Markdown 维护，随站点一起构建。核心实体：

```text
Chapter { id, year, title, narration, heroMediaId, placeIds, routeSummary }
Place   { id, chapterId, name, city, dateRange, summary, heroMediaId, mediaIds, coordinates }
Media   { id, type, url, thumbnailUrl, alt, capturedAt, credit, privacy }
```

页面从内容配置读取章节、地点和媒体；交互状态只保存当前地点、照片查看器状态、动效偏好和声音偏好。内容不复制到全局客户端状态。地点坐标仅显示城市/景点级精度，不公开照片的精确 GPS。

## 8. 技术边界（进入开发后的约束）

- 推荐使用 Next.js、React、TypeScript 和 App Router，路径为 `/`、`/journeys`、`/places/[slug]`。
- 页面负责布局和内容获取；视觉组件负责首屏、章节、地图、地点卡片和照片查看器。
- 图片使用响应式尺寸、WebP/AVIF 和渐进加载；首屏图优先加载，其他章节按浏览进度加载。
- 第二阶段若加入 3D，使用 React Three Fiber/Three.js 作为独立、动态加载的场景模块；它不能承载正文、表单或关键导航，且必须保留静态照片降级。

## 9. 隐私、错误处理与验证

- 发布前清除图片 EXIF、精确 GPS、设备信息和不必要的人脸识别元数据；获得同行者的展示授权。
- 原图不对公开访问者开放；使用适合公开分享的导出尺寸。
- 图片加载失败时显示照片说明和低调占位，不留空白区域；地图加载失败时展示地点列表；动效失败时直接回退静态布局。
- 验收覆盖桌面、手机、触控、键盘、减少动效、慢网、图片失败和无 WebGL 场景。重点验证每个地点页可访问、可分享、可返回，且不依赖动效才能理解内容。

## 10. 分阶段交付

1. **首版**：三幕、六个地点、首页、章节、地点页、地图、全部片段、照片查看器与静态内容配置。
2. **增强版**：更精细的章节转场、可选环境声、路线动画和内容编辑便利性。
3. **沉浸版**：在真实素材和性能预算验证通过后，为首页或地图引入可关闭的轻量 3D 景深/路线场景。

该范围保持首版聚焦：它先是一部可阅读、可分享、在各设备稳定运行的旅行作品，再逐步增加沉浸技术。
